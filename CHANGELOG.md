## [Unreleased]

## [0.1.1] - 2026-11-14

A documentation release of the research prototype. A user gains one guide of 21 chapters ordered by difficulty, a task index, a reference section generated from `describe` and the Python docstrings, and a documentation site at <https://dietmarwo.github.io/CFD-craft/>; the code blocks of these pages are run and their outputs compared by a CI check. Solver behavior is unchanged: the same case gives the same numerical results, and the case and result schemas are unchanged; the build version and the source and executable fingerprints in a result differ, because the version and the sources changed. One runtime string changed: the schema description of the multigrid option in `describe` links the new page. Experimental canyon validation and a successful fine-grid resolution study remain open gates.

### Added

- Documentation restructure. One [guide](docs/guide/README.md) of 21 chapters ordered by difficulty replaces the user manual, the tutorial pages and the integration guides; the first chapter installs with `pip` and runs the smallest case. New pages: a [landing page](docs/index.md), ["How do I …?"](docs/how-to.md) with 82 tasks, a [comparison with OpenFOAM and Ansys Fluent](docs/comparison.md) that uses committed measurements only, a [reference section](docs/reference/README.md) with pages generated from `describe` and the Python docstrings, and index pages for [developers](docs/developer/README.md), [evidence](docs/evidence/README.md) and [history](docs/history/README.md).
- A documentation site built with mdBook and deployed to GitHub Pages (`book.toml`, `docs/SUMMARY.md`, `.github/workflows/pages.yml`); `scripts/check_site.py` verifies every internal reference of the built pages (`CFD-R004`).
- `scripts/check_docs.py` runs the code blocks of the guide, the README files and the reference pages and compares the shown outputs, floats within the tolerance each page declares (`CFD-R003`). `docs/check-counts.json` holds the minimum number of checked blocks per page, so a page cannot lose a checked block unnoticed. A new CI job `docs` runs it on every push with `scripts/generate_reference.py --check` (`CFD-R002`); the OpenFOAM and optimization-job chapters run in the existing opt-in jobs. See [the documentation check](docs/developer/documentation.md).

### Changed

- `docs/` is sorted by reader: `guide/`, `reference/`, `developer/`, `evidence/` (the validation records, moved from `validation/`) and `history/` (the iteration plans). Every old path keeps a permanent stub that links to the new place; the stub of the user manual keeps its headings and maps the 31 example numbers to chapters.
- The README starts with one sentence, the install line and a Python example with its output, and has seven documentation links. `docs/ai-context.md` starts with the run loop and the rules.
- Links in the rustdoc, the package metadata and one schema description of `describe` (the multigrid option) point to the new paths. No solver behavior changed.
- README: links the [overview of the 18 related repositories](https://github.com/dietmarwo/fcmaes-rust/blob/main/docs/repositories.md).
- CI: `retry-runner-shortage.yml` reruns the failed jobs of a release or CI run when every job that did not succeed was cancelled before a runner picked it up (hosted macOS arm64 shortage), up to three attempts. A release is no longer held back until someone reruns it by hand.
- The optional `fcmaes-cfd-worker` pins optimization-jobs `12f9d57` (its 0.4.0 release `602d31a` plus documentation-only changes) and fcmaes-rust `f764a75`, whose crates are unchanged since `583f33a` apart from that pin. The `runner-integration` CI job builds `optimization-run` at the same revision (it built `cc6b03d`). `integrations/run_jobs.py` against it reproduces the recorded objectives (baseline 1.8682465, BiteOpt 1.8657713, GP 1.6799143).
- `.gitattributes` excludes the Python validation suite (`validation/`) from GitHub language statistics, so GitHub reports the repository as Rust.

## [0.1.0] - 2026-11-04

First version, 0.1.0, a research prototype, released on crates.io (`cfd-craft`, `cfd-craft-cli`) and PyPI (`cfd-craft`). Experimental canyon validation and a successful fine-grid resolution study remain open gates; a package release is not physical qualification.

### Added

- API documentation of the `cfd-craft` library for docs.rs: every public item is documented (coverage 15.1% to 100%, `#![warn(missing_docs)]` keeps it there) with units, valid ranges, invariants and diagnostic codes, a landing page with the prototype status, entry points and a quickstart, module overviews and 14 doctests. The doc comments of the case, result and phase-profile types also fill the `description` entries of the schemas that `describe` prints; the schemas' shape is unchanged. The `cfd-craft-cli` crate links its user manual as documentation, and the Python examples load the manual's point-source case from GitHub, so they run from an installed package.
- Releases (from the contributed release-preparation bundle, reviewed): publishable crates with versioned path dependencies, per-crate README and LICENSE; an optional PyO3 binding and Python package (`cfd_craft`: `check`, `simulate` with the GIL released, a bounded per-call Rayon pool, cancel file and Ctrl-C; console script `cfd-craft-python`) whose preflight is the CLI's, moved into the library as `cfd_craft::input`; `python-release.yml` (abi3 wheels for Linux, Windows and macOS plus the sdist, each checked by `validation/check_installed.py` on CPython 3.10 and 3.14) and `publish-crates.yml`, both publishing on a `v*` tag; `scripts/package_version.py` and `scripts/check_release.py`; CI builds the binding on Rust 1.88 and stable and packages both crates. Release-script failures are `CFD-R001 release.<field>`, Python binding failures `CFD-P001 python.<field>` (docs/diagnostics.md).
- Source fingerprints are package-safe: each crate hashes its own sources, manifest and build script plus the root workspace manifest and lockfile in a checkout, or its packaged lockfile; the CLI and binding combine theirs with the core's. Library results now carry the core fingerprint and compiler instead of an empty identity. Fingerprints recorded before 0.1.0 (for example in validation/RESULTS.md) used the earlier definition.
- [F1–F3 optimization tutorials](docs/guide/13-optimization-lessons.md) (contributed by Astra): native LP versus BiteOpt and GP source allocation with fresh superposition replay, a finite sensor-coverage MIP with exhaustive and greedy checks, every coverage-optimal subset's rank and conditioning and held-out inversion, and coupled cavity design with frozen acceptance and two-grid fidelity gates (zero supported designs in both presets). F3's mean squared speed is the trapezoid volume mean of the staggered face velocities, the GP arm's seed and settings are explicit, and lesson failures report `CFD-T001 optimization.<field>`.
- Implicit steady iteration with RANS and constituents (stages P5c, P5d): `implicit_projection` accepts `neutral_rans` (a variable-viscosity momentum matrix with lagged wall functions, then segregated implicit k and ε steps in delta form, profiled as `turbulence_solve`) and constituents (explicit SSPRK2 sub-steps within each outer iteration, at most 16). It keeps the explicit fixed point on the development canyon (round-off pair to 1.5e-10), the empty-ABL check in steady mode (`run_suite.py --abl-steady`), zero floor events, exact mass budgets and receptors, and accepts the 27k and 93k canyons; the predeclared tightening statistic fails for U on one decade, recorded ([results](docs/evidence/implicit-rans.md)). CFD-E046 is removed; CFD-E047 now covers prescribed flow and `implicit_viscous` with RANS; CFD-E057 reports a singular k or ε correction system. `steady_algorithms.py --case canyon` runs the canyon campaign.
- Ten performance iterations ([results](docs/evidence/performance-iterations.md)): seven bit-identical kernel changes pinned by a new kernel-signature regression, inexact inner projections and a non-binding pseudo-time cap as the implicit recipe, a CFL ramp capped at 5, and two-dimensional runs with one cell on a periodic axis (which also fixes the IC(0) factor for faces that join a cell to itself). With the recipe the 24² cavity is 6.8× and the canyon with its tracer 5.4× faster than before the iterations; the 27k canyon with its tracer takes 57.6 s against 2,974 s in the explicit mode. In the hosted paired cavity sweep (run 41361132558) native reaches the 0.01 target at 24² in 0.111× OpenFOAM's solver time and 0.119× its workflow time, more accurately (0.0054 against 0.0090). The accuracy sweep, `compare_backends.py`, `momentum_baseline.py` and the CI dispatch accept `pressure_relative_tolerance`, `max_time_step_s` and a `native_span` of 1.
- With an implicit steady algorithm and constituents, the archived state records the constituents' own pseudo-time (`scalar_time_s`), and `validation/check_fields.py` checks the emitted mass against it; before, an accepted implicit tracer run whose sub-step cap bound failed the independent checker and the VTK export. `preview` keeps a one-cell periodic axis at one cell. A BiCGStab breakdown no longer counts an iteration without operator applications, which the profile checker would reject. `steady_algorithms.py --case canyon` defaults to `implicit_projection`.
- Matched-accuracy measurement (stage M): with `limited_upwind`/`van_leer` and `implicit_projection`, the hosted paired cavity sweep reaches the 0.01 Ghia target at 24² for both backends, with native at 0.74× OpenFOAM's solver time and 0.45× its workflow time, and more accurate (0.0054 against 0.0090); before, native needed 96² and about 826 s ([results](docs/evidence/matched-accuracy.md)).
- Opt-in implicit steady pseudo-time in delta form (`numerics.steady_algorithm`): `implicit_viscous` (SSPRK2 stages with implicit viscosity) and `implicit_projection` (one implicit correction per outer iteration with a Picard first-order upwind and viscous Jacobian, deferred correction, BiCGStab, a CFL ramp and a projection at the pseudo-time step: a SIMPLEC-type coupling). Both keep the explicit fixed point, acceptance and restart identity; `implicit_projection` passes all predeclared gates and reaches the cavity's unchanged gates in 180–300 outer iterations, 18–40× faster than the explicit mode (van Leer: 0.51 s at 24², 3.06 s at 48² on one host). `implicit_viscous` is 1.5–2.2× faster but misses its predeclared fixed-point shrink statistic on one decade per scheme; that failure is recorded ([results](docs/evidence/implicit-steady.md)). Inner work is reported as `momentum_solver_iterations` and profiled as `momentum_solve`. Transient mode (CFD-E045) and prescribed flow (CFD-E047) are rejected; RANS and constituents follow with P5c and P5d (first entry).
- Opt-in conservative second-order momentum advection (`numerics.momentum_advection`: `second_order_upwind`, or `limited_upwind` with `numerics.momentum_limiter` = `van_albada`, `van_leer` or `monotonized_central`): a flux form on the staggered grid with an upwind-biased reconstruction. All predeclared P3a gates pass: operator orders 2.06 (unlimited) and 1.92–1.95 mean L1 (limited), translating-vortex orders 2.0–2.3, momentum conservation to 1e-16, bounded limited schemes, barrier insulation, restart identity and default byte identity. The steady Re=100 cavity reaches 0.005–0.006 Ghia error at 24², where donor-cell needed 96² to reach 0.01 ([results](docs/evidence/second-order-momentum.md)). Stage P3b adds a zero-gradient outlet closure and allows `neutral_rans` after the empty-ABL check (unchanged gates) and the development canyon (zero floor events) passed for all four schemes; `run_suite.py --abl-numerics` reproduces the ABL check. The accuracy sweep and comparator gain `--native-numerics`, CI the `native_numerics` and `momentum_scheme` inputs.
- Anisotropic unmasked pressure multigrid with fixed symmetric line/small-plane
  solves and stiff-axis semicoarsening, exact spacing-aware reuse, block storage
  and work statistics, and independent dense/projection tests. Three-method
  rough-field and coupled-flow campaigns retain failed rows and distinguish
  cold setup from cached solves. The accuracy sweep now records an optional
  native preconditioner. See [anisotropy results](docs/evidence/anisotropic-pressure.md)
  and [remaining performance work](docs/evidence/performance-gap-status.md).

- Opt-in symmetric geometric multigrid/PCG for unmasked pressure, with unchanged fine-equation and residual gates, coefficient-aware hierarchy reuse, strict work profiling and paired benchmarks. Accepted native 48² cavity solver time fell from 180.7 to 74.1 s (2.44×) on the recorded P1 host; IC(0) remains default. The original point smoother struggled with anisotropy; its historical [results](docs/evidence/pressure-multigrid.md) retain the shape sweep that motivated the next substep.
- Opt-in native phase profiling (`cfd-craft profile`, `validation/check_profile.py`): inclusive and exclusive phase times and attempted pressure work beside an ordinary archive, with unchanged results. A cavity cost-versus-error sweep (`compare_backends.py --grid-sweep`, CI selection `external=accuracy`) keeps every row and reports cost at an error target only where repeated accepted runs reach it. On one host, OpenFOAM reaches 0.01 Ghia error at 24² and native does not at 48²; pressure projection takes 78–88% of native solver time in the cavity and canyon flow solves ([baseline](docs/evidence/gap-baseline.md)).
- A detailed user manual with architecture, numerical/evidence concepts and 31 API examples; four executable Rust examples, native/OpenFOAM Python cookbooks and CI checks for the small native workflow. A project banner and prominent README/manual navigation make the entry points easier to find. An error from a `Control::with_poll` callback now stops a library run as `cancelled` instead of `diverged`. `validation/manual_examples.py --foam-root` runs the manual's OpenFOAM recipes in order and reports each step; `prepare-mapped` with a relative runtime root now starts the mapper instead of failing to find it from the target case directory.
- Same-host timing of the lid-driven cavity with both backends (`validation/compare_backends.py`, CI selection `external=comparison`): one thread each, every order of the methods, every run accepted and its work repeated. OpenFOAM's steady workflow is 4.7–5.5 times faster than native steady mode on two hosts and closer to the Ghia reference; its solver process is about 9 times faster ([results](docs/evidence/backend-comparison.md)).
- Faster native pressure solves, momentum and RANS stencils at unchanged results: a flat IC(0) factor and sweeps, a per-solve compact list of face weights for the PCG products, projection without temporary arrays, shared neighbor lookups and a step that copies only the fields it changes. Paired measurements against the previous implementation (`performance_probe` example, `validation/benchmark_native.py`, frozen cases in `cases/performance/`) show 1.46–2.1× faster pressure solves and 1.36–1.87× faster coupled step batches on two hosts, with bit-identical fields. The memory estimate adds 112 bytes per cell, so cases close to their memory allowance can now be rejected by the preflight check.
- Bounded mapped refinement campaigns (`validation/refinement_campaign.py`): a checked complete coarse snapshot bound to the frozen plan, frozen limits and producer identities, mapping once followed by eligible same-mesh stages, archive checkpoints that bind parents, manifests, sealed summaries and producers, separate coarse and fine work, cancellation-safe verdicts and a conditional two-grid observable comparison. A manual CI selector runs the declared level-2 backstep campaign and retains complete fine archives. Original numerical, audit and measurement gates remain unchanged; two grids do not establish mesh independence or physical qualification.
- One-level coarse-to-fine initialization (`prepare-mapped`): Foundation-13 mapNearest volume fields from an accepted cold source, generated target boundaries, a new-mesh phi, a receipt over the source chain, templates, mapper output and logs, an independent replay of the mapping, and runtime and rebuilt-mesh checks. A mapped and a cold level-2 cavity converge to the same fields; `mapped_start.py` reports mapped and cold level-2 backstep starts. Acceptance thresholds are unchanged.
- Verified same-mesh steady field continuation: source/field/runtime/mesh/control receipts, an independent local-flux check of the source, bounded multi-stage backstep execution with stop reasons, cumulative work and separate final acceptance, and restart comparison tools. A run stopped at its iteration limit keeps its final field; limits that would force near per-iteration writes are rejected. Manual CI runs a fixed-work continuation check and compares a staged reference solve with a single run.
- Wall-resolved external backstep recipes (a graded mesh without cell-size jumps, and SIMPLEC/SIMPLE profiles), an independent Cartesian audit of mesh, local face flux and wall y+, and a gated refinement workflow. The SIMPLEC reference converges and passes the audit on its coarse mesh; no mesh pair is claimed. Solver logs with NaN/Inf values or a diverging continuity error stop execution with a preserved failure archive.
- Bounded OpenFOAM Foundation-13 execution with hashed inputs, a checked input copy, runtime/library identity, a fixed child environment, process-group cancellation, hard address-space and per-file limits, independent stored boundary-flux checks and an archive consistency verifier.
- A cavity comparison between the native and external solvers, a frozen Driver--Seegmiller experimental screening protocol, exact raw-data identities, paired downstream profiles, signed skin-friction/reattachment metrics, trivial-predictor baselines and a first-cell y+ estimate. The measurement screen is assessed only for a numerically accepted solve. These do not qualify the native canyon solver.
- A reproducible non-root installer for the tested OpenFOAM package, external execution tests with a synthetic Foundation-13 runtime, and an optional real-backend CI job that runs the study preset.
- Rust flow and passive-transport library and the `cfd-craft` CLI (describe, check, preview, run, report, verify) with strict case and result schemas.
- `check` diagnostics with codes and field paths, including COST 732 domain and blockage warnings for RANS cases; a catalog in docs/diagnostics.md. Run, restart, output and `report` errors carry codes as well.
- Memory and output estimates that bound the measured peak and the written artifacts, including the monitor history and the per-receptor text; a host-memory refusal that comes before any grid allocation.
- `preview`, which checks the coarsened case and compares its solid volume and fluid topology with the original's cell mask without building the original grid.
- Masked-grid pressure projection with one gauge per closed fluid component and IC(0)-preconditioned CG, checked against an independently assembled reference on a masked grid with an outlet, a sealed pocket and a periodic axis.
- Laminar flow with moving walls, and a neutral k–epsilon package with Richards–Hoxey inflow and rough-wall functions.
- Conservative passive transport (linear upwind or MUSCL/MC with SSPRK2), point, line and volume sources, point and volume receptors, and checked restart.
- Steady acceptance over three successive 100-step monitor windows, with recomputed equation residuals and balances.
- Run archives with a manifest, a completion marker and `report` verification; an independent archived-field checker in Python.
- Analytic and reference verification (periodic shear, Gaussian transport, Poiseuille, Couette, lid cavity, a SciPy sparse reference, an empty-ABL consistency check), source inversion and finite-canyon tutorials.
- A command launcher for optimization-jobs and an optional native fcmaes simulation worker.
