# Continue a costly steady solve in verified bounded stages

The adapter's single run is limited to 3600 seconds and 20000 iterations, and a
finer backstep mesh needs more. Same-mesh field continuation lets a steady solve
make progress in separately bounded, auditable stages. It does not interpolate
between meshes or restore a transient simulation's time history.

## Prepare a new stage

Install the validation dependencies and pinned Foundation-13 runtime as in
[OPENFOAM.md](OPENFOAM.md). Use a complete generated source archive, including
its case, mesh, final fields, logs, summary, manifest and completion marker.
Summary/log-only evidence cannot supply a restart.

```sh
python integrations/openfoam_backend.py report SOURCE_RUN
python integrations/openfoam_backend.py prepare-restart --source SOURCE_RUN \
  --iterations 6000 --output NEW_INPUT
python integrations/openfoam_backend.py run --case NEW_INPUT \
  --foam-root ROOT --timeout-s 3500 --output-mib 512 --output NEW_RUN
python validation/audit_openfoam_mesh.py --run NEW_RUN --output NEW_AUDIT.json
```

A verified but numerically unaccepted source makes `report` exit 2; it is
eligible. `prepare-restart` exits 0 for a prepared stage and 1 otherwise, with a
coded field path (CFD-X012 `initial_state.*`). A source is eligible when:

- it is a sealed archive whose execution completed with a final field;
  failed, timed-out and cancelled runs are rejected, including any older saved
  snapshots they contain;
- its final fields are finite, with nonnegative k/nut and positive omega;
- it was generated by the current case generator, with the generated steady
  controls;
- its stored face flux is a solver state: every cell's net face flux divided by
  U_ref times the cell's face-area scale dz*sqrt(dx*dy) is at most 1e-2. Solver
  iterates lie orders of magnitude below that (about 5e-5 for an early SIMPLEC
  iterate); an edited, flipped or permuted face flux gives order one.

The auditor's acceptance measure, max abs(div(phi))*H/U <=1e-4, is recorded in
the receipt but does not decide eligibility. It tracks how tightly the last
pressure solve was stopped and tightens like H/dx with refinement: an early
SIMPLEC iterate at 500 iterations scores 0.0048, while the cold start every run
begins from scores 5.6. The final stage is still accepted only with it.

Fresh output paths are required; occupied paths are preserved, and a failed
preparation leaves no partial stage. The exact runtime and rebuilt mesh must
match the recorded identities before the solve. No physics, mesh or profile
change is accepted by `prepare-restart`; prepare an ordinary cold case for
another model. Cross-mesh mapping is not implemented.

## What is carried forward

U/p/phi and, for SST, k/omega/nut are copied byte-for-byte from the source's
final field directory to the new `0` directory, including their boundary
definitions; their headers keep the source time as `location`, which the
receipt checks. Fixed physics, mesh and sampling dictionaries keep their source
identities. The new controls are the source's with only endTime and
writeInterval replaced.

Local steady pseudo-time and the solver's residual history start afresh. A
split stage's first-iteration residuals match the uninterrupted run's next
iteration to about 1e-12 relative in the laminar cavity, but only to about
1e-4 in the SST backstep, where some turbulence-model state is not carried by
the copied fields; the difference then decays (see the
[results](../validation/RESTART_RESULTS.md)). `numerical.iterations` counts the
new stage; the receipt's `source_completed_iterations` plus it counts solver
work along the chain, not physical time.

The receipt in `case.json` and `summary.json` records the parent case and
manifest, source acceptance and work, the source metadata and controls, copied
field hashes, the actual mesh, fixed inputs, runtime identity and the source
flux checks. These are checked before solving and when verifying an archive;
a stage that solved must carry its runtime and passed mesh check. Keep parent
archives to inspect the chain: the parent hash alone does not provide their
contents. Checksums establish consistency, not authenticity of an untrusted
case; the trusted-input restrictions of the backend still apply.

## Automate bounded stages

```sh
python tutorials/backstep_resolution.py --preset smoke --iterations 6000 \
  --max-stages 4 --timeout-s 3500 --foam-root ROOT --data VERIFIED_DATA \
  --output NEW_STUDY
```

This is the recorded staged run of the wall-resolved reference. The default is
one stage; at most eight are permitted per case. Every stage is retained, and
`continuation_stop_reason` says why the chain ended:

| Reason | Meaning |
|---|---|
| `numerically_accepted` | the stage passed the nonlinear gate; the audit and screen still decide acceptance |
| `converged_without_numerical_acceptance` | the solver reported convergence but the gate failed; another stage would report convergence again at its first iteration |
| `stage_limit` | the last permitted stage completed without convergence |
| `execution_failed`, `execution_timeout`, `execution_cancelled`, `no_final_field` | the stage stopped without an eligible final field |
| `cancelled` | the study was cancelled between stages |
| `source_ineligible: …` | the completed stage cannot seed the next (exit 2; finer meshes are skipped) |

Other preparation, archive or I/O errors stop the workflow with exit 1. The
512 MiB output and 2048 MiB address-space limits apply per stage; disk and time
grow with the number of stages. Automatic resume across separate CI jobs is not
implemented.

A run that stops at its iteration limit writes a final field only when the limit
is a multiple of the write cadence. Preparation therefore uses the largest
divisor of the limit up to 250 as the cadence, and rejects limits without a
divisor between 50 and 250: they would need nearly per-iteration writes of 8 MB
snapshots, which can push a stage into its timeout. Multiples of 50 are always
accepted; 6000 and 20000 keep cadence 250.

## Check continuation

`validation/restart_equivalence.py` runs FIRST iterations, continues them for
SECOND, runs FIRST + SECOND uninterrupted, and compares the two final fields.
`validation/compare_restart.py` compares any continued run with a control:
`--mode fixed-work` for equal work, `--mode converged` for two converged runs,
including their work, audits and measurement metrics. Both exit 0 when the
bounds hold, 2 when they do not and 1 for invalid input (CFD-X013
`comparison.*`). Run `validation/test_restart.py` normally and under
`python -O`; set `CFD_OPENFOAM_ROOT` to include the actual cavity tests. The
[plan](../docs/iterations/04-steady-continuation-plan.md) and
[results](../validation/RESTART_RESULTS.md) keep software equivalence,
nonlinear convergence, measurement screening and physical qualification apart.
